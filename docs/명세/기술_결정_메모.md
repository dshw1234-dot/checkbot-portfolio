# 기술 결정 메모 (MS To Do 재구축)

- 출처: 다른 세션 'Claude와 MS To Do 연결'에서 2026-10-23에 이 세션으로 전달된 메모. 그 세션에서 사용자가 고르고 동의한 결정이라고 적혀 있다.
- 상태: **구현됨.** 2026-10-23 1단계(7fe2d41)부터 이 메모대로 만들었고, 원본 재현은 태그 `v1-원본재현`(2026-10-24). 지금 코드 구조는 `docs/개발_구조.md`가 기준이다(2026-10-30 점검에서 상태 줄을 고침).

## 0. 목표와 제약
- MS To Do와 아주 비슷한 체크리스트 앱을 재구축 → 사용자 취향 기능 추가 → 에이전트용 필드 추가.
- 최종 목표: Claude로 할 일을 추가하고 "그거 해"라고 하면 Claude가 에이전트로 수행한 뒤 완료 처리.
- PC에 하루 종일 켜 둠 → 메모리 사용량이 MS To Do(작업 관리자 기준 약 105MB) 수준이어야 함. 기존 '할 일 수첩' 아티팩트는 Claude 앱(1.5GB) 안에서 돌아가 너무 무거움.
- 동기화는 Claude 앱을 거치지 않는 가벼운 방식.

## 1. 플랫폼
- PC: Tauri(WebView2). Rust 설치 동의. 트레이 아이콘, 시작 시 자동 실행, 전역 단축키 사용.
- 아이폰: PWA(홈 화면에 추가). iOS Tauri는 보류(Mac·Xcode·Apple Developer 필요).
- 웹 코드는 하나로, PC Tauri와 아이폰 PWA가 같이 씀.
- 금지: Electron, 무거운 프레임워크. 화면은 **Preact**로 정함(`package.json` 의 `preact` 10, 빌드는 Vite).
- Tauri 전용 API는 어댑터 파일 하나(예: `platform.js`)로 감싸 화면 코드가 Tauri에 직접 의존하지 않게 함.

## 2. 데이터: 로컬 우선
- 기기 저장소: IndexedDB + Dexie.
- 화면은 로컬 db만 읽고 씀. 동기화는 뒤에서 따로.

## 3. 동기화: Supabase(무료 등급) + 직접 구현
- outbox(올리지 못한 변경) + lastSyncedAt 커서.
- 쓰기 즉시 업로드 시도, 온라인이면 1초 안에 서버 반영.
- 충돌: 필드 단위 last-write-wins(필드별 updatedAt). CRDT 안 씀.
- 삭제: `deleted: true` 묘비.
- 여러 값이 묶인 필드(반복 규칙 등)는 통째로 바뀌는 문자열로 저장.
- 화면에 "올리지 못한 변경 n건" 표시. 기기마다 마지막 동기화 시각을 서버에 기록(1분에 한 번까지).
- 갱신 주기(2026-10-29 사용자 결정 "MS To Do 주기로"): 화면이 보이는 동안 5초마다 받는다. 근거는 MS 공식 안내 "Microsoft To Do는 5초마다 업데이트되므로"(support.microsoft.com, Microsoft To Do 계정 동기화). 숨은 동안은 60초. 받을 것이 없으면 요청 한 번(빈 응답)이라 무료 등급으로 충분하다.
- 아이폰 PWA: 앱을 열 때와 visibilitychange 때 받아 옴.
- 보안: Supabase Auth + RLS. Firebase는 SDK가 무겁고 구조가 묶여서 제외.

## 4. 알림
- 웹 푸시 구현 안 함. 기한은 화면 표시만.

## 5. 에이전트(나중 단계, 지금은 스키마에 자리만)
- **2026-10-24 자세한 설계가 `에이전트_설계.md`로 승인됨.** 아래 메모와 다른 점은 그 문서가 기준: 필드 이름(`agent`·`agentStatus`·`agentPlan`·`agentResult` 등), 통로는 로컬 CLI, 아이폰 통로는 원격 제어 먼저, Supabase 공식 커넥터는 쓰지 않음.
- Claude는 Supabase에 직접 접근(PC: 스크립트 또는 MCP로 REST, iOS: Supabase 커넥터 → 이후 좁은 권한으로 축소).
- 필드 안: `agent`(bool), `agentStatus`(대기/진행 중/확인 필요/완료), `result`(결과 요약, 산출물 경로).
- 되돌리기 어려운 일은 실행 직전 '확인 필요'로 멈춤. 실행 규칙은 앱 코드가 아닌 Claude 스킬로.

## 6. 개발 순서(권장)
1. 목록·할 일·단계·메모(MS To Do 기본 화면)
2. Supabase 동기화
3. 반복·기한·내 하루 등
4. 사용자 취향 기능
5. 에이전트 필드와 스킬

- 스키마는 처음부터 동기화를 고려: 모든 레코드에 `id`(클라이언트 생성 UUID), 필드별 `updatedAt`, `deleted`, `deviceId`.
