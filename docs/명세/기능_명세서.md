# 기능 명세서: MS To Do 재현 (원본 기준선)

- 관찰 대상: Microsoft To Do Windows 앱 2.178.8571.0, 2026-10-23, 사용자 PC(어두운 테마).
- 관찰 방법: 화면만 봄(메뉴는 열고 닫기만). 데이터를 바꿔야 알 수 있는 동작은 **[확인 필요]** 로 표시했다.
- 표시: **재현** = 그대로 만든다 / **제외** = 사용자가 필요 없다고 함 / **대체** = 그대로는 못 만들어 다른 방식으로 / **보류** = 정해야 함.
- 기술 기준: `기술_결정_메모.md`(PC Tauri + 아이폰 PWA, 로컬 우선 + Supabase). 사용자 확인 뒤 확정.
- 이 문서가 **"원본 재현" 기준선**이다. 사용자 취향 기능은 이 문서를 고치지 않고 `추가_기능.md`에 따로 쌓는다(아래 10장).

## 4. 할 일 오른쪽 클릭 메뉴

나의 하루에 추가(Ctrl+T) / 중요로 표시 / 완료됨으로 표시(Ctrl+D) / ─ / 오늘까지 / 내일까지 / 날짜 선택 / ─ / 다음 위치로 작업 이동… › (다른 목록들) / ─ / 작업 삭제(Delete, 빨강) — **재현**

## 5. 일정 계획 패널(전구, 오늘 할 일)

- 오른쪽에 패널: 제목 "일정 계획" + ✕. 묶음 "최근 추가됨"(오른쪽 …). 각 줄: 원 · 제목 · "목록 이름 · 단계" · 오른쪽 "+"(오늘 할 일에 추가). 아래 "더 보기".
- 다른 묶음(어제, 곧 마감 등)은 이번에 없었음 [확인 필요]. — **재현**

## 10. 추가 기능을 대비한 구조(구현 단계에서 확정)

- **기준선 보존**: 이 명세대로 만든 상태를 git 태그(예: `v1-원본재현`)로 남긴다. 취향 기능은 그 뒤 커밋으로 쌓아서, 원본과의 차이를 언제든 비교할 수 있게 한다.
- **문서 분리**: 원본 동작은 이 문서, 사용자 취향 기능은 `추가_기능.md`(기능마다 ID `X-01`…, 원본의 어느 ID를 바꾸는지 적음).
- **코드 분리**(기술 메모와 같은 방향):
  - `core/` 날짜·반복·정렬·필터 규칙(화면 없는 순수 함수, 테스트하기 쉬움)
  - `data/` Dexie 저장소와 동기화(outbox, 필드별 updatedAt)
  - `ui/` 화면(왼쪽 메뉴, 목록, 세부 정보 창, 메뉴들)
  - `platform.js` Tauri 전용 기능(항상 위, 자동 실행, 인쇄, 배지)을 감싸는 어댑터
  - `features/` 추가 기능. 기능 하나 = 폴더 하나. 정해진 끼움 자리에만 붙인다:
    행 메타 표시, 오른쪽 클릭 메뉴 항목, 세부 정보 창 칸, 스마트 목록, 설정 항목, 할 일 필드.
- **스키마 여유**: 할 일 레코드는 처음부터 `id`(UUID), 필드별 `updatedAt`, `deleted`, `deviceId`를 갖고, 추가 기능 필드(예: 에이전트 `agent`, `agentStatus`, `result`)를 넣어도 기존 화면이 깨지지 않게 모르는 필드는 그대로 보존한다.
