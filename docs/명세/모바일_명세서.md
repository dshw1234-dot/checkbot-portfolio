# 모바일 명세서: 좁은 화면(아이폰 PWA) 재현 기준

- 관찰 대상: 안드로이드 Microsoft To Do(어두운 테마), '휴대폰과 연결' 미러링으로 2026-10-23 관찰. 사용자가 보내 준 아이폰 MS To Do 스크린샷(메뉴, 새 목록)도 참고.
- 적용 범위: 화면 폭 **760px 이하**. 넓은 화면(PC)은 `기능_명세서.md` 그대로.
- 원칙: **만드는 것은 아이폰 앱**이다. 안드로이드에서 본 동작(밀기, 길게 누르기, 시트, 입력 칩)은 따르되 모양은 아이폰 관례에 맞춘다(뒤로 단추 "‹ 이름", 가로 점 ⋯, 키보드 위 띄움, 아래쪽 안전 영역).
- 표시: **재현** / **제외** / **보류**(다음에 정함) / **유지**(지금 우리 앱 방식 그대로, 사용자 지시). "PC와 다름" 칸은 `기능_명세서.md`의 ID 기준.
- 실험은 MS To Do의 '과찰용 테스트' 목록(이름 오타)에서만 했다. 관찰 중 '작업' 목록에 실수로 생긴 할 일 "ㅅㄷㄴㅅ"는 지웠다. **'과찰용 테스트' 목록(할 일 2개)은 사용자가 직접 지운다.**

## 12. 애니메이션

- **측정 방법(2026-10-23~24):** 안드로이드 MS To Do를 '휴대폰과 연결' 미러링 창으로 띄우고 PC에서 ffmpeg로 60fps 녹화(폰 자체 녹화는 미러링을 끊어 쓰지 못함). 조작은 스크립트로 2초 간격, 같은 동작 3번씩. 시간은 프레임 타임스탬프로 잰 첫 변화~마지막 변화, 모양은 움직인 영역만 자른 모음 그림으로 판단. 기록: 공유 메모 폴더 `anim-log.md`.
- **정밀도:** 미러링이 실제로 초당 15~20장만 갱신해서 한 번 측정 오차는 **±50ms**. 그래서 시간은 3번의 중앙값을 50ms 단위로 반올림했고, 곡선은 프레임이 적어 **추정**(안드로이드 기본값과 맞는지로 판단)이다.
- **바탕 규칙:** 목록 행 변화는 안드로이드 RecyclerView 기본 애니메이터와 같은 순서·시간이다: **빠짐(투명해짐) 120ms → 자리 이동 250ms → 들어옴(나타남) 120ms**. 곡선 표기: 표준 = `cubic-bezier(.4,0,.2,1)`, 감속(들어올 때) = `cubic-bezier(0,0,.2,1)`, 가속(나갈 때) = `cubic-bezier(.4,0,1,1)`.
- **구현 원칙:** transform·opacity만 움직인다(높이·위치 속성 애니메이션 금지). `prefers-reduced-motion: reduce`면 모두 끈다(지금 규칙 유지). 화면 전환은 마운트 때 CSS 키프레임, 닫을 때는 '나가는 중' 클래스를 붙였다가 끝나면 내림. 목록 행 이동은 FLIP(바뀌기 전후 위치 차이를 Web Animations API의 translateY로).
