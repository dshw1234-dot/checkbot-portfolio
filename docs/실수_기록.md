# 실수 기록과 자기 검사 장치

Claude 가 이 앱을 만들며 저지른 실수를 갈래별로 모으고, 같은 실수를 **사람이 아니라 검사가 먼저 잡게** 만든 장치를 적는다.
새 실수가 나면 여기에 한 줄 더하고, 되도록 회귀 테스트와 함께 남긴다. (2026-10-24 세션 기록 7개, 약 90건 조사에서 시작)

## 다섯 관문

```
코드 고침 ─▶ npm run check ─▶ 커밋(훅) ─▶ 배포(판 확인) ─▶ 실기·서버 대조
             BOM·lint·테스트     check:fast     미커밋 중단       설정→진단
             화면·빌드           안 돌면 막힘    version.json      server-check
```

| 관문 | 명령 | 잡는 것 |
|---|---|---|
| 1. 전체 검증 | `npm run check` (약 30초) | BOM·깨진 JSON, hooks 규칙 위반, 단위 테스트, 화면 흐름(PC 폭·375px, 콘솔 오류 0), 빌드 |
| 2. 커밋 훅 | `.githooks/pre-commit` → `npm run check:fast` (약 10초) | 1의 앞 세 단계를 안 돌리고 커밋하는 것. `sync.mjs --start` 가 연결. 급하면 `--no-verify`, 그 뒤 반드시 `npm run check` |
| 3. 배포 검사 | `npm run deploy` | 커밋 안 한 변경이 섞여 올라가는 것(멈춤, `--force` 로 지나감), 공개 주소가 새 판을 내보내는지(`version.json` 의 commit 이 HEAD 와 같아질 때까지 기다림, `--check` 로 따로) |
| 4. 진단·대조 | 앱 설정 → 진단(복사·내보내기), `window.__todoDiag()`, `node scripts/server-check.mjs [--compare 진단.json]` | 기기마다 개수가 다른 것, 올리지 못한 변경, 옛 판으로 도는 기기, 서버에만·기기에만 있는 id |
| 5. 규칙 | `CLAUDE.md` "끝났다고 말하기 전에" | 확인 안 한 것을 확인했다고 말하는 것, 실데이터 실험, 셸로 파일 쓰기 |

### 4. 빌드·배포 판 불일치(9건)
PWA 가 10분 캐시로 옛 판(1bd067e), 시작 메뉴 바로가기가 옛 exe, 설정 화면 "모든 변경을 올렸습니다"가 옛 판에서 뜸, 다른 세션의 미커밋 변경이 배포에 실릴 뻔.
- **장치:** 관문 3. 판 번호가 앱(설정 → 진단)·`version.json`·서비스 워커 캐시 이름에 들어간다. PC 앱도 같은 빌드를 쓰니 진단의 판 번호로 옛 exe 를 알아본다.
- 2026-10-24 `npm run tauri build` 가 켜져 있는 앱의 exe 를 못 지워 실패 → `Stop-Process` 로 앱만 강제 종료하고 다시 빌드 → 사용자가 다시 연 PC 앱이 **목록·로그인이 다 빈 채** 뜸(진단: 새 기기 id, 로그인 안 됨). 원인: 종료가 덜 끝난 WebView2 가 저장소를 쥐고 있을 때 새 앱이 떠서 디스크 저장소(IndexedDB·Local Storage) 대신 빈 임시 저장소로 돌았다. 디스크 파일은 그대로였다(leveldb `LOG` 가 새로 열린 흔적 없음). 앱을 닫고 `msedgewebview2.exe`(명령줄에 `com.dshw.todo`)가 0개가 된 뒤 다시 켜자 원래 기기 id·로그인·개수 그대로 돌아옴. **장치:** 규칙(`CLAUDE.md`): 빌드 전 앱을 닫을 때는 WebView2 프로세스가 다 끝난 것을 확인하고, 다시 켠 뒤 진단의 기기 id·로그인이 전과 같은지 본다. 빈 화면이면 지우거나 로그인하지 말고 먼저 저장소 폴더(`%LOCALAPPDATA%\com.dshw.todo\EBWebView\Default`)를 백업한다.
