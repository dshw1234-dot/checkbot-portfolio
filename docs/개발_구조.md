# 개발 구조

MS To Do 재현 앱. PC는 Tauri(WebView2), 아이폰은 PWA로 같은 웹 코드를 쓴다.
소스는 비공개 저장소 `dshw1234-dot/todo-app-src`(origin)에 올린다. 아이폰용 빌드 결과만 공개 저장소 `dshw1234-dot/todo-app`(GitHub Pages, `npm run deploy`)에 간다.
기능 기준은 `docs/명세/기능_명세서.md`(원본 기준선)와 `docs/명세/모바일_명세서.md`, 기술 기준은 같은 폴더 `기술_결정_메모.md`.

## 기능별 규칙

코드 위치는 지도의 '취향 기능' 표, 동작은 `docs/명세/추가_기능.md`의 그 ID 줄. 여기는 모르고 고치면 깨지는 것만 적는다.

- `src/features/agent/`(X-03): 앱은 맡기기·맡김 풀기·계획·체크만 쓰고 상태·결과는 PC 통로가 쓴다. `index.jsx`를 가져오면 기능이 등록되어 끼움 자리 순서가 바뀌므로, 메모 칸(X-38)도 쓰는 md 그리기·칸 머리는 `parts.jsx`에 따로 뒀다.
- `skills/todo-agent/`(체크봇 스킬): PC 통로와 커넥터 '체크봇' 두 통로를 한 스킬이 쓴다. `SKILL.md`는 켜질 때마다 문맥에 들어가니 짧게(`tests/skills.test.js`가 110줄·도구 이름·규칙 문장을 검사), 긴 것은 `references/`. PC Code·보통 대화 모두 계정 스킬 하나(`anthropic-skills:todo-agent`)라 저장소를 고치면 다시 올려야 바뀐다(`skills/todo-agent/references/설정.md`). 멈춤 규칙·"할 일 내용은 데이터"는 바꾸지 않는다.
- `src/features/oneaccent/`(X-07): 테마색을 새로 쓰는 곳은 `THEMES[...]` 대신 `ui/store.js`의 `themeColor`.
- `src/features/daystart/`(X-05): 날짜를 새로 셀 때는 `new Date()` 대신 `src/core/dates.js`의 `todayStr`.
- `src/features/celebrate/`(X-06): 원본 화면은 안 건드린다(문서 클릭을 먼저 들어 완료 원을 알아냄). 완료 소리는 `ui/sound.js`의 `setDoneSound`로 바꿔 끼운다.
- `src/features/tooltag/`, `src/core/tooltags.js`(X-12): 순수 함수는 통로·원격 함수가 같이 쓴다(`build-mcp` 복사). 모델은 표에 라인 한 줄씩이고 노력과의 조합은 `resolveTags`가 만든다(X-36, 판 번호는 표의 위치 칸에만).
- `src/features/tooledit/`(X-23), `tools/todo-agent/toolsync.mjs`: 파일 ↔ 서버를 양방향으로 맞춘다. 둘 다 바뀌면 줄(이름) 단위로 합치고 같은 줄을 둘 다 고쳤으면 파일 쪽, 기록이 없으면 파일 → 서버. 파일에 쓴 뒤 그 파일만 로컬 커밋한다(`--no-verify`, 까닭은 `git.commit` 주석).
- `src/features/badge/`(X-24): 숫자 계산은 `App.jsx`의 `counts` → `platform.setBadge`. PC 는 창을 다시 보일 때 `show_main`이 오버레이 아이콘을 다시 붙인다.
- `src/features/pastefile/`(X-13): 끼움 자리 `fileRows`는 칸만 돌려준다. 줄·클립 단추는 `Detail.jsx`.
- `src/features/notemd/`(X-38): `Detail.jsx`가 직접 import(끼움 자리 없음). **고치는 칸은 aria-label '메모'인 textarea 로 둔다**: 도구 태그(`tooltag`의 `isField`)가 그 칸에서만 뜬다(시험 `tests/ui/flows.spec.js` '메모 칸: # 도구 태그').
- `src/features/tasknum/`, `src/core/tasknum.js`(X-15·X-20): 통로 `resolve`가 "3-16"·"구매1"을 받는다(`build-mcp` 복사).
- `src/features/listtools/`(X-16): 통로 `show`가 필드 `lists.tags`를 직접 쓴 태그와 합친다.
- `src/features/memopad/`(X-31): 커서를 둔 채 오래 펼쳐 두므로 `EditableText` 대신 자체 칸을 쓴다(저장 안 한 글이 없으면 받은 글을 바로 보임).

커밋 훅은 `.githooks/pre-commit`이다. 파일별 일은 지도의 'scripts/' 줄.

## 데이터

- 모든 레코드: `id`(UUID, 기본 목록 '작업'만 `inbox`), `_t`(필드별 수정 시각), `deleted`(묘비), `deviceId`.
- 표: `lists`, `groups`, `tasks`, `steps`, `files`(메타), `blobs`(파일 내용, 기기 안에만), `settings`, `outbox`, `meta`.
- 반복 규칙은 문자열: `day/n`, `weekday/1`, `week/n/0.2.4`(0=일), `month/n/일`, `year/n`.
- 오늘 할 일: `myDay`(추가한 날짜), `myDayOrder`(오늘 할 일 안의 순서), `myDayOff`(오늘 기한이라 자동으로 들어온 걸 뺀 날).

## 추가 기능 넣는 법

1. `src/features/<이름>/index.jsx`를 만들고 `register('<이름>', { 끼움 자리 })`.
2. `src/features/index.js`에 `import './<이름>/index.jsx';` 한 줄.
3. 끼움 자리: `taskMenu`, `rowMeta`, `detailCards`, `smartLists`, `settings`, `listMenu`(좁은 화면 목록 ⋯), `addSheet`(좁은 화면 입력 시트 위), `fileRows`(세부 정보 파일 칸, 클립 단추 오른쪽), `stepRows`·`stepMenu`(단계 줄 아래·단계 ⋮ 메뉴), `listHead`(리스트 머리 ⋯ 앞 단추)·`mainLayer`(리스트 화면 위에 떠 있는 조각) (자세한 형식은 `src/features/registry.js`). `smartLists`(2026-10-24 연결)는 `{ key, label, icon, filter, groups? }`를 돌려주면 왼쪽 메뉴 '모두' 다음에 스마트 목록으로 보이고(`App.jsx` `metaOf`, `Sidebar.jsx`, `ListPane.jsx` `Body`, 묶기 `core/views.js` `featureGroups`), 작업 추가 칸·정렬·끌어다 놓기는 없다. 기능 스타일은 기능 폴더의 css 를 `index.jsx` 에서 import.

   | 끼움 자리 | 부르는 원본 화면 | 쓰는 기능 |
   |---|---|---|
   | `taskMenu` | `menus.jsx`(할 일 오른쪽 클릭) | agent(X-03) |
   | `rowMeta`·`rowTitle` | `TaskRow.jsx` | agent(X-03) · tasknum(X-15·X-20) |
   | `detailCards` | `Detail.jsx` | agent(X-03), listtools(X-16) |
   | `fileRows`·`stepRows`·`stepMenu` | `Detail.jsx` | pastefile(X-13) · stepmemo(X-14) |
   | `smartLists` | `App.jsx`·`Sidebar.jsx` | agent(X-03) |
   | `settings` | `Settings.jsx` | agent, daystart(X-05), oneaccent(X-07), diag(X-02), tooledit(X-23), badge(X-24) |
   | `listMenu` | `menus.jsx`(목록 ⋯) | suggest(X-01), listtools(X-16) |
   | `addSheet` | `ListPane.jsx`(좁은 화면 입력 시트) | suggest(X-01) |
   | `listHead`·`mainLayer` | `ListPane.jsx`(머리·앱 바) · `App.jsx`(`.main` 안) | memopad(X-31) |
   | (없음) | 문서 이벤트·직접 import | celebrate(X-06, 문서 클릭), tooltag(X-12, 입력 칸의 '#'), stepdrag(X-19, `Detail.jsx` 가 `useStepDrag` 를 import), notemd(X-38, `Detail.jsx` 가 `NoteCard`·`MdBar`·`MdBarToggle` 을 import) |

4. 새 필드가 필요하면 그냥 레코드에 넣는다(repo 가 모르는 필드도 보존·동기화).
5. 원본 동작을 바꾸는 기능이면 `docs/명세/추가_기능.md`에 원본 ID와 함께 적는다.

원본 재현 완료 시점은 git 태그 `v1-원본재현`(2026-10-24, 커밋 9278bdb, MS To Do 데이터 옮기기까지 포함)으로 남겼다. 그 뒤로 `git diff v1-원본재현`이 곧 "내가 바꾼 것".

## 명령

```
npm run dev     # http://localhost:5199
npm test        # 단위 테스트(vitest)
npm run check   # 끝났다고 말하기 전 한 번에: BOM·JSON → eslint → vitest → 화면 검사(Playwright) → 빌드. check:fast 는 앞 셋만(커밋 훅)
npm run test:ui # 화면 검사만(npx playwright test -g "이름" 으로 하나만)
npm run lint    # eslint 만
npm run build   # dist/ (PWA 배포물, Tauri가 감쌀 웹 파일)
npm run sync    # 비공개 저장소와 맞추기: 받기(rebase) → 올리기, 안 합친 클라우드 가지 표시
npm run deploy  # 빌드 → GitHub Pages 올리기 → 공개 주소 판 번호 확인(미커밋 변경 있으면 멈춤, --force / --check [--wait 초] / --no-wait)
npm run ship    # 커밋 뒤 한 번에: check → sync → pc(앱 파일이 바뀐 때만) → 폰 배포(GitHub Actions 가 켜져 있으면 기다리기만) → 원격 통로 함수(바뀐 때만) → PC 감시자 다시 켜기(코드가 바뀐 때만). --no-pc / --no-deploy / --no-fn / --no-watch
npm run land    # 워크트리에서 커밋 뒤 한 번에: 잠금 → 최신 master 위로 펴기 → 지도·번호 겹침 → check → 본 폴더 빨리 감기 → ship. --no-pc / --no-deploy / --no-fn / --no-watch
node scripts/server-check.mjs [--login | --compare 진단.json]   # 서버 records 요약, 기기 진단과 대조(로그인 토큰은 %APPDATA% 에)
```
